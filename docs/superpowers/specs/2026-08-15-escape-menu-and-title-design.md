# Esc 메뉴, 로비 편의 기능, 시작 타이틀 설계

## 목표

게임 플레이 중 `Esc`로 접근할 수 있는 메뉴를 제공한다. 사용자는 게임을 계속하거나 화면 모드를 바꾸고, 최초 화면(Homescreen)으로 돌아가거나 앱을 종료할 수 있다. Homescreen 로비에서는 방 번호를 한 번에 복사할 수 있고, 앱을 시작하면 어두운 분위기의 `Preternatural` 타이틀 연출이 재생된다.

## 결정 사항

| 항목 | 결정 |
| --- | --- |
| 네트워크 구조 | 현재 Relay + NGO 호스트 권위 구조를 유지한다. 게임 진행 중 완전한 호스트 마이그레이션은 포함하지 않는다. |
| 호스트 이탈 | 게임 진행 중 호스트 이탈은 현행처럼 세션 종료 후 전원 Homescreen 복귀. 게임 시작 전 로비에서는 다음 참가자에게 세션 호스트 권한을 넘긴 후 나간다. |
| Esc 동작 | `GameScene`에서만 메뉴를 열고 닫는다. Homescreen과 사망 화면의 기존 입력은 변경하지 않는다. |
| 싱글플레이 메뉴 | 로컬 게임 시간을 정지하고, 마우스 커서를 보인다. |
| 멀티플레이 메뉴 | 네트워크 시간과 다른 플레이어는 정지하지 않는다. 메뉴를 연 로컬 플레이어의 이동·시점 입력만 비활성화한다. |
| 화면 설정 | `창 모드 (1920×1080)`와 `전체 화면` 두 가지. 선택은 `PlayerPrefs`에 저장하고 앱 시작 시 적용한다. |
| 로비 복귀 | 싱글은 Homescreen을 직접 로드한다. 멀티는 `SessionManager.LeaveRoomAsync`를 통해 연결 종료 후 Homescreen으로 복귀한다. |
| 종료 | 빌드에서는 `Application.Quit`, Unity 에디터에서는 Play 모드를 종료한다. |
| 방 번호 복사 | 방 코드와 함께 `복사` 버튼을 보이고, 클릭 시 시스템 클립보드에 저장한 뒤 상태 문구를 갱신한다. |
| 타이틀 연출 | Homescreen 진입 시 어두운 반투명 오버레이 위에 `Preternatural`을 표시한다. 글자는 낮은 빈도의 불규칙한 밝기·알파 깜빡임을 보이고 약 2.5초 후 사라진다. 클릭·키 입력으로 즉시 건너뛸 수 있다. |

## 구성

### 1. `InGameEscapeMenu`

`GameScene`에만 표시되는 코드 생성 uGUI Canvas를 소유한다. 기존 `MultiplayerMenu`처럼 씬 YAML에 버튼 리스너를 직렬화하지 않고 런타임에 Canvas·버튼·EventSystem 연결을 만든다.

- 버튼: `계속하기`, `화면 설정`, `처음 화면으로`, `게임 종료`
- `Esc`는 열림/닫힘 토글이다. 메뉴가 열린 경우 `계속하기`와 동일하게 닫는다.
- 열 때 커서를 풀고, 닫을 때 기존 1인칭 조작 상태에 맞게 다시 잠근다.
- 싱글 경로는 `Time.timeScale`을 열기 전 값으로 보관했다가 닫을 때만 복구한다. 메뉴가 아닌 흐름에서 시간을 바꾸지 않는다.
- 멀티 경로는 `Time.timeScale`을 바꾸지 않는다. 로컬 소유의 `PlayerMovement`와 `FirstPersonCamera`만 잠시 비활성화하고, 메뉴를 닫거나 씬을 떠날 때 원래 활성 상태를 복구한다.
- `처음 화면으로`은 중복 클릭을 막는다. 멀티에서는 SessionManager가 이미 맡는 NetworkManager 종료와 Scenes 복귀 흐름을 재사용한다.

### 2. `DisplayModeSettings`

표시 모드의 저장·적용 책임만 가진 작은 런타임 클래스다.

- 창 모드: `Screen.SetResolution(1920, 1080, FullScreenMode.Windowed)`.
- 전체 화면: `Screen.fullScreenMode = FullScreenMode.FullScreenWindow`.
- 설정 변경 즉시 적용하고, 정수 모드 값을 `PlayerPrefs`에 저장한다.
- 앱 시작 시 저장값이 없으면 현재 Player Settings 기본값인 1920×1080 창 모드를 적용한다.
- 해상도 목록, 그래픽 품질, 다중 모니터 선택은 이번 범위에 포함하지 않는다.

### 3. 로비 보완

`MultiplayerMenu`의 로비 표시 영역에 방 코드 `복사` 버튼을 추가한다.

- `GUIUtility.systemCopyBuffer`에 현재 Join Code를 저장한다.
- 성공 시 상태 문구를 `방 번호를 복사했습니다.`로 갱신한다.
- 코드가 없는 상태에서는 버튼을 노출하지 않거나 비활성화한다.

`SessionManager`는 시작 전 로비의 자발적 호스트 이탈만 처리한다.

- 세션이 Homescreen에 있고, 호스트 외 참여자가 있으면 두 번째 참가자의 ID를 새 호스트로 지정하고 변경을 저장한다.
- 변경 성공 후 기존 호스트만 세션을 나가 Homescreen에 남는다. 모든 클라이언트는 `SessionHostChanged`로 로비 UI를 다시 그린다.
- 게임 씬이거나 참가자가 없으면 현행 종료 경로를 유지한다. 이 제한은 NGO 게임 상태를 안전하게 유지할 수 없는 호스트 마이그레이션을 흉내 내지 않기 위함이다.

### 4. `HomeTitleSequence`

Homescreen 전용의 코드 생성 Canvas 연출이다.

- 기존 Homescreen 및 MultiplayerMenu Canvas보다 뒤에 배치하되, 기존 버튼 이벤트를 가로채지 않는다.
- 어두운 전체 화면 오버레이와 중앙 대형 TMP 글자 `Preternatural`을 생성한다.
- `Time.unscaledDeltaTime`으로 재생해 설정 메뉴/시간 정지와 무관하게 정상 종료한다.
- 무작위 시드는 사용하지 않고 사전에 정한 짧은 알파·밝기 패턴을 반복해 테스트와 재현성을 확보한다.
- 2.5초가 지나거나 사용자 입력이 있으면 페이드아웃 후 Canvas를 파괴한다. Homescreen 재진입 시 다시 재생한다.

## 영향 및 안전성

- 기존 싱글 시작 버튼, 멀티플레이 방 생성/입장, 게임오버 화면은 수정하지 않는다.
- 멀티플레이에서는 메뉴가 로컬 UI일 뿐 동기화되는 게임 상태가 아니다.
- 호스트 이전은 로비의 세션 소유자만 바꾼다. 게임 중 호스트의 NetworkObject·Relay allocation·몬스터 권위는 이전하지 않는다.
- 씬에 새 컴포넌트나 버튼을 수동으로 배선하지 않도록 코드 생성 UI와 기존 NetBootstrap 배선 패턴을 따른다.

## 검증

1. EditMode 테스트로 화면 모드 저장값의 기본값·왕복 적용·유효하지 않은 값 폴백을 검증한다.
2. EditMode 테스트로 로비 호스트 이탈 대상 선택(두 번째 참가자, 참여자 없음)을 검증한다.
3. Unity Editor 컴파일 후 새 Console 오류가 없는지 확인한다.
4. Play Mode 싱글 경로에서 Esc 열기/닫기, 커서, 시간 정지, Homescreen 복귀, 에디터 종료 동작을 확인한다.
5. 로비에서 방 생성, 코드 복사, 호스트 이탈 뒤 남은 참가자의 시작 버튼 전환을 두 인스턴스로 확인한다.
6. 멀티플레이 GameScene에서 Esc 메뉴가 다른 참여자를 멈추지 않으며 로컬 입력만 막는지 확인한다.
7. macOS 빌드에서 타이틀 연출, 창/전체 화면 전환, 실제 앱 종료를 확인한다.

## 제외

- 게임 진행 중 NGO 호스트 마이그레이션 또는 Distributed Authority 전환
- 전용 서버 배포
- 해상도·품질·오디오·키 바인딩 설정 메뉴
- 로비 텍스트 채팅, 방 목록, 준비/강퇴 기능
